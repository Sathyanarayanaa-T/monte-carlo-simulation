# Project Notes & Architecture Decisions

## 1. Decisions (Resolved)

- **D1 (Item Counts & Keying)**: Item counts and reverse-keyed items stay at the placeholder values from SPEC.md Section 3.4 ($A\text{-}i: 5, A\text{-}ii: 4, B\text{-}i: 5, B\text{-}ii: 4, B\text{-}iii: 6, C: 4$, with 1 reverse-keyed item per construct). Simulation results are conditional on them; the key scenarios are re-run with real counts after the survey pilot.
- **D2 (Semester Distribution)**: Semester is categorical and uniform over $\{6, 7, 8\}$ with equal probability $1/3$, and has no true effect on $C$.
- **D3 (Ceiling-Shift Direction)**: Ceiling shift applies in the scored direction (`ceiling_shift_direction: scored | raw`, default `scored`). In scored mode, the shift pushes every item toward category 5 of its scored scale; for reverse-keyed items, the shift is subtracted from the raw propensity before discretisation ($x^* - \text{shift}$), so post-scoring ($6 - x$) yields elevated endorsement at category 5 without inducing spurious acquiescence when $\gamma = 0$. Marker items are unaffected.
- **D4 (Pearson Item Correlations)**: Item correlations are computed using standard Pearson product-moment correlations on item scores. The real-data empirical analysis uses the exact same functions; polychoric correlation is treated as a real-data sensitivity analysis and is not simulated.
- **D5 (Parallel Analysis Factor Retention)**: Horn's parallel analysis retains factors sequentially (Horn rule) up to the first component where the sample eigenvalue falls below the 95th percentile null benchmark ($\lambda_k \le \lambda^*_{crit, k}$). If the first eigenvalue fails, 0 factors are retained.
- **D6 (Factor Loadings Sampling)**: `loading_draw` defaults to `equispaced` across the specified loading interval (e.g., $[0.55, 0.85]$ for base; $[0.40, 0.65]$ for low-reliability). This ensures empirical reliabilities ($\alpha, \omega$) reliably land within their target bands ($[0.75, 0.85]$ and $[0.55, 0.70]$) without stochastic sample clustering. `random` remains available for sensitivity analysis.
- **D7 (Nonlinear Orthogonalisation)**: `orthogonalise_nonlinear` defaults to `true`. When true, the planted non-linear functional term (bilinear product or threshold term) is residualised against the linear latent predictors ($A_{\text{tech}}, A_{\text{mkt}}, B\text{-}i, B\text{-}ii, B\text{-}iii$) on the calibration population, ensuring that $\psi$ is strictly the pure orthogonal non-linear variance share with $R^2(\text{linear}) = 0.0$. When false, the unorthogonalised threshold $R^2$ on the linear predictors is approximately 0.333 (measured), conflating linear and non-linear predictive power.
- **D8 (Structural-Validity Gate)**: The structural-validity gate asks (a) how often an A-i/B-i HTMT above 0.85 is flagged when B-i items cross-load 0.3 on A-i, and (b) how often the base design is falsely flagged (at most 5 percent); both are evaluated at n=100 and n=150 from the Tier 1 shards with MCSE; no interpolation to n=120.
- **D9 (Tier 2 Scenario Selection & Null Refits)**: Tier 2 (`reduced_ml`) comprises exactly the 14 scenarios specified in Part D: $\{\text{none}, \text{inter\_small}, \text{inter\_med}, \text{thresh\_small}, \text{thresh\_med}\}$ at $n \in \{100, 150\}$ (10 scenarios), plus $\{\text{none}, \text{inter\_med}\}$ at $n \in \{50, 300\}$ (4 scenarios). Replications are set to 300 with $B = 50$ null refits for residual-resampling interaction tests, unless the slow calibration test shows the interaction test is miscalibrated, in which case $B$ increases to 100 and Tier 2 is re-timed.
- **D10 (Compute Parallelism)**: Execution parallelism is fixed to `n_jobs = 6` in `config/methods.yaml`. Threadpools (`OMP_NUM_THREADS`, `OPENBLAS_NUM_THREADS`, `MKL_NUM_THREADS`) are pinned to 1 to avoid thread thrashing and CPU oversubscription.
- **D11 (Scale Differences as Stated Limitation)**: The simulation uses 5-point Likert items for $C$, $B\text{-}i$, and $B\text{-}ii$. The real-world FEDRS survey uses a 7-point scale for $C$ and behavioral count formats for $B\text{-}i$ and $B\text{-}ii$. This is accepted as a stated methodological limitation in the dissertation, with no re-run required unless the pilot data suggests substantial distortion.
- **D12 (Parquet Storage & Provenance Tracking)**: Output parquet shards (`results/*.parquet`) are excluded from git tracking (added to `.gitignore`). Data provenance is guaranteed because each shard embeds the git commit hash, UTC timestamp, and pinned package versions directly into its Parquet schema metadata table and JSON sidecar. Raw results are backed up independently.
- **D13 (Top-k Recovery Rule)**: Replaced scenario-level NaN rule. Top-$k$ recovery is defined only if the oracle importance of the $k$-th ranked feature exceeds that of the $(k+1)$-th by at least 10 percent relative ($(v_k - v_{k+1}) / v_k \ge 0.10$); otherwise NaN for that $k$ only. Evaluated per $k$ (Top-1 and Top-2). Kendall $\tau_b$ is preserved across all scenarios.
- **D14 (Tuning-Conditional Null)**: The residual-resampling interaction null test (SPEC.md Section 5) runs once per replication on the full dataset fit (never inside CV folds). The null refits reuse the hyperparameters selected on the observed dataset (M4: `min_samples_leaf`; M5: `max_depth` and `n_estimators`; M6: fixed hyperparameters). This conditional-on-tuning formulation isolates the test statistic distribution while keeping computation manageable.
- **D15 (Cached Parallel-Analysis Thresholds)**: Parallel analysis 95th percentile null eigenvalue thresholds are cached per process by $(n_{\text{obs}}, n_{\text{items}})$, computed once using a fixed seed derived deterministically from $(n_{\text{obs}}, n_{\text{items}})$. Simulation replication results do not depend on the replication seed for null eigenvalue generation, eliminating redundant Monte Carlo draws across replications.
- **D16 (Tier 2 Staged Execution)**: Tier 2 runs in stages of 100 replications up to 300 (100, 200, 300). This bounds single-session compute, allows intermediate inspection of convergence and power, and leverages chunked replication-level resume.
- **D17 (Tuning-Conditional Bootstrap)**: The 50-bootstrap ranking stability refits reuse the hyperparameters selected on the observed dataset (M4: `min_samples_leaf`; M5: `depth` and `n_estimators`). Hyperparameters are not re-tuned inside each bootstrap resample, isolating feature importance variance from hyperparameter search variance while drastically reducing computational overhead.
- **D18 (Replication-Level Resume)**: Output rows are committed to parquet shards in chunks of 25 replications. When re-running with a larger `--reps` or resuming an interrupted job, only missing replication IDs are evaluated and appended. Seed determinism is guaranteed because `SeedSequence.spawn(k)` creates child seeds identical to the first $k$ children of any larger spawn.
- **D19 (Null-Calibration Check and Pass Band)**: Evaluated on `base_n100_none` via `scripts/null_calibration.py`. Nominal Type I error rate ($\alpha = 0.05$) should fall within approximately two Monte Carlo standard errors of $0.05$ (e.g. $[0.01, 0.09]$ at $R=100$). If empirical rejections for M4 or M5 exceed $0.10$, that method is switched to full re-tuning inside each null resample and re-timed.
- **D20 (Cross-Loading 0.5 Scenarios)**: Empirical evaluation of $0.3$ cross-loading yielded an HTMT flag rate ($> 0.85$) of $< 1\%$ (mean HTMT $\approx 0.67$), failing to support the Milestone 3 claim ($> 85\%$). To provide adequate coverage for the structural-validity gate, four sensitivity scenarios with cross-loading $0.5$ (`sens_cross_loading_0p5_n{100,150}_{none,inter_med}`) were added, expanding Tier 1 from 60 to 64 scenarios (Tier 2 unchanged at 14).
- **D21 (Symmetric Cross-Loading)**: Cross-loading is configured explicitly via `cross_loading_pairs: [["B_i", "A_tech"], ["B_ii", "A_mkt"]]`. Each listed construct loads symmetrically onto its paired latent domain (B-i onto A-i/A_tech, and B-ii onto A-ii/A_mkt) with sensitivity weights 0.3 and 0.5. Constructs not listed (e.g. B-iii) do not receive extra cross-loadings.
- **D22 (Provisional Gate Rule)**: Provisional structural-validity gate rule flags a scenario replication if Parallel Analysis extracts fewer than 2 factors OR HTMT exceeds 0.85 on any construct pair. Starting evaluation criteria are $\le 5\%$ false-flag rate on clean/base constructs and $\ge 70\%$ detection rate on severe violations (cross-loading 0.5, contaminated $\kappa=0.4$). Final rule threshold selection is informed by empirical results in `reports/gate_check.txt`, where HTMT alone proved insensitive to small-item construct collapse and Parallel Analysis showed sensitivity to high latent correlation.
- **D23 (High Latent Correlation Scenarios)**: Added four sensitivity scenarios (`sens_high_latent_corr_n{100,150}_{none,inter_med}`) setting the structural regression weights $A_{\text{tech}} \leftarrow B_i$ and $A_{\text{mkt}} \leftarrow B_{ii}$ to 0.60 with no cross-loading, keeping residual variances strictly positive ($0.5635$ and $0.5725$). Tier 1 expands from 64 to 68 scenarios (Tier 2 remains 14).
- **D24 (Core Group Execution Priority)**: Production simulation runs support `--group core|sens|all` in `src/run.py` and `scripts/run_tier.sh`, where `core` consists of the 28 base and null scenarios ($n \in \{50, 100, 150, 300\}$) and `sens` covers the 40 sensitivity scenarios. Staging executes the core group first before running sensitivity expansions.
- **D25 (Report Numbers Provenance Rule)**: Every quantitative metric, reliability value, flag rate, or timing number reported in documentation and milestone reports must originate from an executable script output saved directly to `reports/<name>.txt`.
- **M2a Interaction Term Clarification**: In Model M2a, the pre-specified bilinear interaction term for the interaction DGP is $A_{\text{tech}} \times B\text{-}i$ (matching the true planted form $A_{\text{tech}} \cdot B\text{-}i$). For the threshold DGP, M2a uses $A_{\text{tech}} \times B\text{-}iii$, which acts as an approximate parametric proxy for the localized threshold mechanism $B\text{-}iii \cdot \mathbf{1}[A_{\text{tech}} < -0.5]$.
